# AnimalTracker: iPhone app for AAC button presses, feed, poop, health check-ins, an oral AI check-in, and voice recording with meaning analysis, for any animal

Date: 2026-09-16
Status: design v6, awaiting approval
Supersedes: `2026-09-15-animal-tracker-app-design-v5.md` (AnimalTracker v5, copied into this repo) and `2026-09-15-cat-voice-design.md` (Animal Voice). Same two products merged into one app.

## Purpose

Ash keeps animals (currently a horse) and is teaching them to press recordable sound buttons. She wants one app to log button use, feed, poop, and daily wellbeing check-ins per animal, by hand on her iPhone or by talking once a day to an AI assistant that fills in the records and asks follow-up questions. She also wants to record an animal's vocalizations, tag what the animal was doing and what she thinks the sound meant, and over time have the app tell her, per animal, what a new sound most likely means with an honest confidence. All records and audio stay on the phone; only check-in transcript text is sent to the AI.

## Rulings that resolve the two source specs

1. **Local only, no iCloud, no Sign in with Apple.** AnimalTracker v5 requires no iCloud and personal signing; both CloudKit and Sign in with Apple need a paid developer team. The combined app stores everything locally (`cloudKitDatabase: .none`) and relies on export and import for backup. This reverses the Animal Voice choice of iCloud sync and Sign in with Apple. Cost if wrong: the persistence layer is one file; sync can be added later without touching domain code.
2. **Media as files.** Photos, videos, and voice recordings are files under `Documents/Media/`, visible in the Files app. Voice audio is not stored as a SwiftData blob.
3. **One selected animal.** The nav-bar animal switcher from AnimalTracker is the single place an animal is chosen. Recording a voice clip uses the selected animal, which satisfies "log which animal before recording". Voice tags still show the animal and allow changing it afterwards.
4. **First-party packages are not third-party dependencies.** The audio and stats code live in two local Swift packages inside the repo so they can be tested with `swift test` on the Mac. No external packages.
5. **Product name AnimalTracker.** Bundle id `com.ashlab.AnimalTracker`, Xcode project generated by XcodeGen from `project.yml`. The two packages keep their existing names `AnimalVoiceAudio` and `AnimalVoiceStats` because they are the voice subsystem.

## Constraints

- iPhone only, native SwiftUI, iOS 17 minimum, Swift 5 language mode. Built with Xcode 26.6 (iOS 26.5 simulator installed), installed on the phone with personal signing.
- No iCloud sync, no analytics, no third-party dependencies. The only network use is the oral check-in, which sends transcript text to the Anthropic Messages API over HTTPS using the user's own API key. Voice recordings, photos, and videos never leave the phone.
- Any number of animals of any species. One animal is selected at a time; every screen shows that animal's data.
- Logging a button press must be one tap. Logging a normal poop must be two taps. A Health check-in must reach the camera in one tap. Starting a voice recording must be one tap once an animal is selected.
- Photos, videos, and audio are stored as files in `Documents/Media/`, exposed to the Files app for backup. Videos are capped at 60 seconds. Voice recordings are capped at 5 minutes.
- Voice analysis (segmentation, pitch, MFCC, classification) runs fully on-device.

## Top-level navigation

Tab bar with five tabs: **Buttons**, **Feed**, **Poop**, **Health**, **Voice**. Every tab's navigation bar has, on the left, the selected animal's name and avatar as a menu that switches animals or opens Manage Animals; on the right, a microphone icon that opens the oral check-in and a gear icon that opens Settings.

On first launch with zero animals, the app opens Manage Animals with an Add Animal form.

## Data model (SwiftData, local store, `cloudKitDatabase: .none`)

All entities have `id: UUID`, `createdAt: Date`. Enums are stored as String raw values. Every domain record below the Animal has an `animal` relationship; deleting an animal is blocked in the UI while it has records (archive instead).

### Animal

`Animal`: name, species (free text with suggestions: horse, pony, donkey, dog, cat, goat, sheep, cow, pig, chicken, rabbit, other), colorHex, photoFilename (optional, stored like Health media), tracksOutdoorTime (Bool, default true for horse, pony, donkey, goat, sheep, cow, pig, chicken; false otherwise; editable), sortOrder, isArchived, note (optional). `isCat` is true when any word (split on non-letters) of the lowercased species is "cat", "cats", "kitten", or "kitty" (so "cattle" is not a cat) and gates the voice research hint.

Selected animal id lives in `@AppStorage("selectedAnimalId")`. If it points at an archived or missing animal, the first non-archived animal is selected.

### Buttons domain

`AACButton`: label (the word on the physical button), colorHex (chosen to match the marker on the physical button), sortOrder, isArchived, animal, presses (relationship, no cascade; archive instead of delete when presses exist).

`Press`: timestamp (editable), button (relationship), kind (`PressKind` = prompted | spontaneous), note (optional), editedAt (optional).

### Feed domain

`FeedDay`: date (calendar day, unique per animal, stored as local start-of-day), outdoorHours (Double?, 0 to 24, shown only when the animal tracksOutdoorTime), outdoorAreaAcres (Double?, >= 0, same visibility), note (optional), animal, feedings (cascade delete).

`Feeding`: time (Date), note (optional), day (relationship), items (cascade delete).

`FeedItem`: category (`FeedCategory` = forage | food | supplement | treat), type (free text, e.g. "hay", "Purina Senior", "kibble", "MSM"), amount (Double), unit (free text, e.g. "flakes", "lb", "scoop", "cup", "g"), sortOrder, feeding (relationship).

Hay is a forage item ("hay, 2 flakes"). There are no hay-specific fields. Suggestions for `type` and `unit` are derived at query time from the selected animal's existing FeedItem values per category, most recent first, falling back to all animals.

### Poop domain

`PoopTag`: name, colorHex, isBuiltIn, isHidden, sortOrder. Global across animals. Seeded on first launch with: normal, soft, loose, runny, hard, dry, mucus, blood, green, undigested food, foul smell, small volume, large volume, none today. Built-in tags can be hidden and renamed but not deleted. Custom tags can be deleted only when unused.

`PoopObservation`: timestamp, tags (many-to-many with PoopTag), note (optional), editedAt (optional), animal.

### Health domain

`HealthCheckIn`: timestamp, photoFilename (optional), videoFilename (optional), note (optional), editedAt (optional), animal. At least one of photo, video, or note must be present. Filenames are relative to `Documents/Media/`; files are not stored in SwiftData.

Media files are named `<uuid>-photo.jpg` (JPEG, longest side downscaled to 2048 px, quality 0.85), `<uuid>-video.mov` (as captured, max 60 s), and `<uuid>-thumb.jpg` (300 px). Deleting a check-in deletes its files.

### Voice domain

`VoiceRecording`: recordedAt, durationS, audioFilename (`<uuid>-audio.m4a`, mono AAC 48 kHz, relative to `Documents/Media/`), status (`VoiceStatus` = recorded | analyzed | noSounds | failed), errorMessage (optional), note, activityTag (String?), meaningTag (String?), userConfidence (Int? 1 to 3), editedAt (optional), animal, vocalizations (cascade delete). Deleting a recording deletes its audio file.

`Vocalization`: startS, endS, f0Mean?, f0Min?, f0Max?, f0Slope?, voicedFraction, rmsDb, spectralCentroidHz, mfcc ([Double], 13 values), activityTag?, meaningTag?, userConfidence?, overridden (Bool), recording (relationship). Labels live on vocalizations; tagging a recording copies its tags to every vocalization that is not overridden.

`VoiceTag`: kind (`VoiceTagKind` = activity | meaning), name, isBuiltIn, sortOrder. Global across animals. Seeded on first launch with species-neutral activities (eating, waiting at door, being petted, playing, alone, greeting a person, looking out window, at the vet, on a walk, other) and meanings (hungry, wants attention, wants out or in, greeting, annoyed, in pain or distress, content, alert or warning, unknown). Users add their own. "Unknown" is never used as a training label.

### Oral check-in domain

`OralCheckIn`: startedAt, endedAt (optional), status (`CheckInStatus` = inProgress | reviewed | saved | discarded | failed), model (String), inputTokens, outputTokens, createdRecordIds ([UUID] as JSON string), errorMessage (optional), animal, turns (cascade delete).

`CheckInTurn`: index, role (`user` | `assistant`), text, timestamp, draftJSON (optional, assistant turns only), checkIn (relationship).

### Settings (`@AppStorage`)

| Key | Default | Meaning |
|---|---|---|
| selectedAnimalId | none | current animal |
| sequenceWindowSeconds | 10 | max gap between presses grouped into one sequence |
| defaultPressKind | spontaneous | kind applied on tap unless toggled |
| hasSeededPoopTags | false | one-time seed guard |
| hasSeededVoiceTags | false | one-time seed guard |
| speakQuestions | true | read assistant questions aloud |
| hasAcknowledgedCheckInPrivacy | false | one-time notice guard |
| checkInQuestionCap | 8 | max follow-up questions per session |

The Anthropic API key is stored in the iOS Keychain (service `AnimalTracker`, account `anthropic-api-key`), never in UserDefaults, the store, or exports.

## Manage Animals

List of animals with avatar, name, species. Add (name, species with suggestions, color, optional photo from camera or library, tracksOutdoorTime toggle prefilled by species), edit, reorder, archive/unarchive. Delete allowed only when the animal has no records in any domain, including voice recordings.

## Buttons tab

Segmented control at the top: Log, History, Stats, Manage. With zero buttons for the selected animal, the tab opens on Manage.

### Log
- Grid of large tiles, one per non-archived button of the selected animal, ordered by sortOrder. Tile background is the button color; label in high-contrast text.
- Segmented toggle above the grid: Spontaneous / Prompted. Starts at the default kind and resets after every logged press.
- Tap a tile: insert a `Press` with `timestamp = now`, the toggle's kind, no note. A 3-second toast reads "Logged Out (spontaneous)" with Undo, which deletes that press.
- Long-press a tile: opens a note sheet for the most recent press of that button if logged within the last 60 seconds; otherwise logs a new press and opens the note sheet.
- Empty state when all buttons are archived: link to Manage.

### History
- List, newest first, sectioned by calendar day.
- Presses grouped into sequences using `sequenceWindowSeconds`. One-press sequence: color dot, label, time, kind badge, note preview. Multi-press sequence: one row with labels joined by arrows ("Out → Treat"), start time, disclosure to the individual presses.
- Swipe to delete a press. Tap to edit timestamp, kind, note.

### Stats
- Range picker: 7 days, 30 days, All.
- Chart 1: presses per button, horizontal bar, stacked prompted vs spontaneous, colored by button.
- Chart 2: presses per day, stacked bar by button.
- Chart 3: time-of-day heatmap, hour by button.
- Sequence table: each distinct ordered sequence of two or more distinct buttons with count, sorted by count. Then per-button repeat counts.
- Empty state when no presses in range.

### Manage
- List of the selected animal's buttons with swatch and label. Add (label + color from a palette of 12 plus custom), rename, recolor, reorder, archive/unarchive. Delete only with zero presses.

## Feed tab

- List of the selected animal's `FeedDay` rows, newest first: date, outdoor hours and acres (if tracked), feeding count. A "Today" button opens today's day card, creating it if missing.
- Day card: outdoorHours and outdoorAreaAcres fields (hidden when the animal does not track outdoor time), note, then feedings in time order, "Add Feeding".
- Feeding editor: time picker; four sections (Forage, Food, Supplements, Treats), each a list of `FeedItem` rows (type with suggestions, amount, unit with suggestions) plus an Add row; note. "Copy last feeding" prefills items from the animal's most recent feeding (excluding the one being edited) and can be undone by cancelling the editor.
- Swipe to delete a feeding or item. Deleting a day requires confirmation.

## Poop tab

- Quick-add bar: tag chips (non-hidden tags in sortOrder, multi-select), a note field, Save. Save inserts a `PoopObservation` for the selected animal at the current time, then clears the selection. Save is disabled with zero tags.
- Below: observations grouped by day, newest first. Row: time, tag chips in tag colors, note preview. Swipe to delete, tap to edit.
- Manage tags lives in Settings.

## Health tab

- Top: a large "Check in" button opening the in-app camera in photo mode, with a switch to video (60 s cap). After capture, a sheet shows the media, an optional note with quick-insert chips (acting normally, lying down more, off food, lethargic, limping, vomiting, coughing, scratching, other), and Save. "Note only" skips media. "From library" attaches an existing photo or video, copied into `Documents/Media/`.
- Below: check-ins grouped by day, newest first, with thumbnail or video badge or note icon, time, note preview. Tap to open full screen: zoomable photo, playable video, editable note and timestamp, Add photo / Add video if missing, Delete with confirmation.
- Camera and library permission strings in Info.plist. If camera permission is denied, Check in opens the note-only sheet with an explanation.

## Voice tab

Segmented control at the top: Record, History, Ask, Insights. All four apply to the selected animal.

### Research basis

The Lund University Meowsic project (Schötz, van de Weijer, Eklund) applied phonetic methods to cat vocalizations and reports that meows in positive or requesting contexts tend to be short with a high, rising fundamental frequency (f0), while meows in negative contexts tend to be long with a low, falling f0 ([Schötz et al., "Phonetic Methods in Cat Vocalisation Studies: A report from the Meowsic project", Lund University research portal](https://portal.research.lu.se/en/publications/phonetic-methods-in-cat-vocalisation-studies-a-report-from-the-me/); [Meowsic studies page](https://meowsic.se/studies.html) [project website, not peer-reviewed]). That is why the first-class features are duration, f0 statistics, and f0 contour slope. Spectral shape features (centroid, MFCCs) are added because individual animals differ and per-animal discrimination needs timbre, which is mechanistically plausible rather than proven. The Meowsic finding is about cats, so the research hint is shown only for animals whose species is a cat.

Sample data for tests: `cat1.m4a` (91 s, mono, 48 kHz AAC, a cat) kept as a test fixture together with a 16 kHz WAV made with ffmpeg. The specified segmenter yields 12 segments on it.

### Record
- Big record button, live level meter, elapsed time, stop. Disabled with an explanation when no animal is selected. 5-minute cap.
- On stop: the m4a is moved into `Documents/Media/`, a `VoiceRecording` is inserted for the selected animal, segmentation and feature extraction run in a background task, then the tagging sheet opens.
- Tagging sheet: animal (prefilled with the selected animal, changeable), activity, meaning, confidence (guess, fairly sure, certain), notes. New activity or meaning tags can be typed in. Save applies the tags to every detected vocalization not overridden. "Later" leaves the recording untagged.

### History
- Recordings for the selected animal, newest first, filter by activity or meaning. Row: date, duration, sound count, tags.
- Recording detail: playback, tags with edit, list of vocalizations (start, duration, pitch, tag, "edited" marker) each playable in isolation; tap a vocalization to override its activity, meaning, and confidence, or reset to the recording's tags. Re-analyze with a sensitivity slider (10 to 40 dB below the loudest sound), which replaces the vocalizations and re-applies the recording tags. Delete with confirmation removes the audio file.

### Ask
- Record a new sound for the selected animal. The recording is saved like any other, then each detected vocalization shows: the predicted meaning and probability, bars for every meaning, the animal's leave-one-out accuracy with n, the five nearest labeled past sounds with play buttons, the cat-only research hint with attribution, and a "This was actually…" picker that saves the correct label on that vocalization (overridden) so the ask becomes training data.
- Below the readiness threshold, the screen says how many more labeled sounds each meaning needs instead of predicting.

### Insights
- Readiness status, leave-one-out accuracy, labeled and unlabeled counts, a scatter of duration versus pitch mean colored and symbol-coded by meaning (at most six meanings plus "Other", fixed order by count then name, palette validated for colorblind separation in light and dark), and a table of labeled sounds per meaning.

## Oral check-in sheet

Opened from the microphone icon. Applies to the selected animal. First use shows a notice: transcript text, the animal's name and species, button labels, poop tag names and recent feed item types are sent to Anthropic; audio, photos, voice recordings and stored records are not. If no API key is set, the sheet explains and links to Settings.

Flow:
1. **Talk.** A large record button. Speech is transcribed live with `SFSpeechRecognizer` (`requiresOnDeviceRecognition = true` when supported). The live transcript is shown and editable as text before sending. Microphone and speech permission strings in Info.plist; denial shows a text-entry fallback.
2. **Extract.** The transcript is sent to Claude (see Claude request). The response is a `CheckInDraft` plus `missing` and `nextQuestion`.
3. **Follow up.** If `nextQuestion` is non-null and the question count is below `checkInQuestionCap`, the question is shown and, if `speakQuestions`, spoken with `AVSpeechSynthesizer`. The user answers by voice or text; the answer is appended and step 2 repeats with the full history. Saying "done", "skip", "that's all" or tapping Finish ends the loop.
4. **Review.** The draft is mapped onto records for the selected animal: today's `FeedDay` (created or updated), zero or more `Feeding`s with `FeedItem`s, at most one `PoopObservation`, at most one `HealthCheckIn` (note only). Each shown with its tab's editor. Token usage shown. Save commits all in one transaction and marks the `OralCheckIn` saved; Cancel marks it discarded but keeps the turns.

Required fields, asked one at a time in this order: outdoor hours and area (only if the animal tracksOutdoorTime); forage fed and how much; food fed, type and amount; supplements given; poop normal or which tags; any wellbeing concern. Declined fields stay blank and are not asked again.

`CheckInDraft` (Codable, mirrors the JSON schema sent to the API):
- `feedDay`: { outdoorHours: Double?, outdoorAreaAcres: Double?, note: String? }
- `feedings`: [{ time: String? (HH:mm local), items: [{ category: "forage"|"food"|"supplement"|"treat", type: String, amount: Double?, unit: String? }], note: String? }]
- `poop`: { tags: [String] (from the provided list), note: String? }?
- `health`: { note: String? }?
- `missing`: [String] from the fixed field-key list
- `nextQuestion`: String?
- `done`: Bool

Mapping rules: a feeding with null `time` gets the check-in start time. Unknown tags are dropped and listed on Review as "unrecognized: ...". Out-of-range numbers are clamped and flagged. If today's `FeedDay` exists, non-null draft fields overwrite it and Review says so.

### Claude request

- `POST https://api.anthropic.com/v1/messages` with `x-api-key`, `anthropic-version: 2023-06-01`, and the server-side fallback beta header. Body: `model: "claude-opus-5"`, `max_tokens: 4096`, `thinking: {type: "adaptive"}`, `fallbacks: "default"`, `output_config.format` = the `CheckInDraft` JSON schema (strict), `system` = fixed prompt, `messages` = conversation so far. Exact header names and body shape are taken from the bundled `claude-api` skill reference at implementation time, not from memory.
- System prompt: role (assistant filling an animal care log), the animal's name and species, whether outdoor time is tracked, today's date and local time, button labels, the poop tag list, up to 20 recent feed item types and 10 units as vocabulary hints, the required-field list and question order, instructions to ask exactly one short question at a time (under 20 words), never invent values, set `done` when nothing required is missing or the user declines.
- Response handling: check `stop_reason` first. `end_turn` with parseable JSON proceeds. `refusal` or unparseable JSON opens Review with an empty draft and the raw transcript; the `OralCheckIn` is marked failed with the reason. `max_tokens` retries once asking for brevity.
- `URLSession`, 60 s timeout, one automatic retry on connection failure or HTTP 429/5xx. No streaming.
- `ClaudeClient` is a protocol with a live `URLSession` implementation and a scripted test double.

## Logic (pure, testable, no SwiftData imports)

Snapshot structs (`PressSnapshot`, `FeedingSnapshot`, `PoopSnapshot`, `HealthSnapshot`, `AnimalSnapshot`) mirror the models so logic and IO tests never touch the container.

`Sequencer.group(presses, window) -> [Sequence]`: input sorted ascending; consecutive presses with gap <= window join a sequence.

`StatsAggregator`: `countsPerButton`, `countsPerDay`, `hourHeatmap`, `sequenceCounts` (>= 2 distinct labels), `repeatCounts` (1 distinct label, >= 2 presses).

`FeedSuggestions.types(items, category)` and `.units(items)`: distinct, most recent first, case-insensitive dedupe keeping most recent casing.

`SpeciesDefaults.tracksOutdoorTime(species) -> Bool`.

`CheckInSession` (`@Observable` state machine): idle -> recording -> extracting -> asking -> recording ... -> reviewing -> saved | discarded | failed. Depends only on `ClaudeClient` and `Transcriber` protocols.

`DraftMapper.map(draft, animal, today, existingDay, tags, now) -> MappedRecords` with `warnings`.

`ClaudeRequestBuilder.build(system, messages, schema) -> URLRequest` and `ClaudeResponseParser.parse(data) -> ClaudeResponse` (stop reason, JSON text, usage), tested against recorded fixtures.

`MediaStore` protocol (file-backed implementation plus in-memory test double): `savePhoto` (returns the photo filename and the thumbnail filename it generated), `saveVideo`, `saveAudio`, `url(for:)`, `exists(_:)`, `delete`. Downscaling and thumbnail generation are pure functions over image data.

### Voice packages (already planned in detail in `docs/superpowers/plans/2026-09-15-cat-voice.md`, tasks 2 to 13)

`AnimalVoiceAudio` (Accelerate, AVFoundation): `AudioLoader` (any file to 16 kHz mono Float32), `Segmenter` (40 ms frames, 20 ms hop, active within 20 dB of the loudest frame and above -50 dBFS, drop runs under 80 ms, bridge gaps under 100 ms), `PitchTracker` (YIN, 60 to 3000 Hz, voiced when aperiodicity < 0.3), `SpectralAnalyzer` (1024-point FFT, hop 320, 26 slaney mel bands, 13 MFCCs, librosa-compatible), `FeatureExtractor` producing `VocalFeatures` (21-column vector, NaN for missing), `Recorder` (AVAudioRecorder, m4a, live level). f0 statistics ignore voiced frames more than an octave from the median voiced f0 (octave-error rejection); voicedFraction counts all voiced frames.

`AnimalVoiceStats` (pure Swift): `Standardizer` (NaN-aware), `KNNClassifier` (k = 5, distance-weighted), `NaiveBayesClassifier` (Gaussian, variance floor), `Ensemble` (average), `Evaluator.leaveOneOut`, `Readiness` (at least 2 meanings with at least 5 labeled sounds each), `ResearchPrior.hint(species:…)` (cats only).

App-side voice services: `AnalysisService` (file to vocalizations), `PredictionService` (labeled vocalizations of the selected animal to a prediction with neighbors, accuracy, and hint), `InsightsModel`, `TagPropagation`.

## Data handling

- Export via share sheet from Settings, all animals, with an `animal` column on every CSV row:
  - `presses.csv`: `animal,timestamp_iso8601,button,kind,note`
  - `feedings.csv`: one row per FeedItem: `animal,date,outdoor_hours,outdoor_area_acres,feeding_time_iso8601,category,type,amount,unit,feeding_note`. A feeding with no items produces one row with empty item columns.
  - `poop.csv`: `animal,timestamp_iso8601,tags (pipe-separated),note`
  - `health.csv`: `animal,timestamp_iso8601,photo_filename,video_filename,note`
  - `voice-recordings.csv`: `animal,timestamp_iso8601,duration_s,audio_filename,status,activity,meaning,confidence,note`
  - `vocalizations.csv`: `animal,recording_id,start_s,end_s,f0_mean,f0_min,f0_max,f0_slope,voiced_fraction,rms_db,spectral_centroid_hz,mfcc0..mfcc12,activity,meaning,confidence,overridden`
  - `animal-tracker.json`: `{ "version": 4, "animals", "buttons", "presses", "feedDays", "feedings", "feedItems", "poopTags", "poopObservations", "healthCheckIns", "oralCheckIns", "checkInTurns", "voiceTags", "voiceRecordings", "vocalizations" }`. Media files (photos, videos, audio) are not embedded; they live in `Documents/Media/`, visible in the Files app (`UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`).
- Import JSON: merges by id (update existing, insert new). Shows counts and asks for confirmation. Check-ins or recordings with missing media show a placeholder.
- Undo covers only the last logged press. All other changes go through edit screens.

## Error handling

- SwiftData save failures surface as an alert; the change is not shown as saved.
- Import rejects unknown `version` or dangling references (record to missing animal, press to missing button, item to missing feeding, observation to missing tag, vocalization to missing recording), naming the problem.
- Deleting an animal with records, a button with presses, or a tag in use is blocked with an explanation to archive or hide instead.
- Numeric clamps: outdoor hours 0 to 24, acres and amounts >= 0.
- Oral check-in: missing API key, denied microphone or speech permission, no network, HTTP errors (401, 429, 5xx), refusal, unparseable output each show a specific message; the transcript is never lost; Review is always reachable.
- Media write failures surface as an alert and the check-in or recording is not saved. Missing files on disk show a placeholder.
- Voice: microphone permission denied explains and links to Settings; no vocalization detected keeps the recording with status `noSounds` and offers re-analysis; feature extraction failure sets `failed` with the error and keeps the audio playable.

## Out of scope

Automatic press detection by microphone, cloud sync of any kind, Sign in with Apple, cross-animal or cross-domain correlation views (for example correlating voice meanings with feed), pooled cross-animal or per-species voice models, species-specific analysis parameters beyond the cat-only hint, reminders, widgets, watch app, photo editing, media compression settings, extracting button presses from speech, sending audio, photos or voice recordings to the AI, streaming responses, species-specific feed templates beyond the outdoor-time toggle.

## Addendum v7 (2026-09-19): Supabase backend and Sign in with Apple

Ash asked for secure login via Apple ID and a Supabase backend, and set the push-to-main milestone as: login works, animals can be tracked, and audio can be recorded and analyzed. This supersedes ruling 1 above.

- **Auth.** Native Sign in with Apple (`ASAuthorizationAppleIDProvider`, nonce-hashed) exchanged with Supabase Auth via `signInWithIdToken(provider: .apple, idToken:, nonce:)` using the supabase-swift package. A sign-in screen gates `RootTabView`; Settings gains Sign out. The session is persisted by the SDK. Sign in with Apple requires the app to be signed with a paid Apple Developer team; the Apple provider must be enabled in Supabase Auth with the app bundle id `com.ashlab.AnimalTracker` as an allowed client id. DEBUG builds keep a "Continue offline" button so the simulator can be exercised without an Apple account; release builds do not.
- **Third-party dependency.** `supabase-swift` (Auth, PostgREST, Storage) is allowed; nothing else.
- **Server schema (milestone).** Tables `animals`, `voice_recordings`, `vocalizations`, `voice_tags` mirror the SwiftData models field for field (snake_case), plus `user_id uuid references auth.users`, `updated_at timestamptz`, `deleted_at timestamptz null`. Row Level Security: a user reads and writes only rows where `user_id = auth.uid()`. Audio lives in a private Storage bucket `voice-audio` at `<user_id>/<audioFilename>` with the same ownership policy. Later domains (buttons, feed, poop, health, check-ins) get tables the same way after the milestone.
- **Sync model.** SwiftData stays the working store so the app works offline. Synced models gain `updatedAt: Date`. Every local save enqueues a `SyncOutbox` row (entity, record id, op upsert or delete, JSON payload, createdAt); `SyncService` drains the outbox to PostgREST upserts and Storage uploads when online, and pulls rows with `updated_at > lastPulledAt` per table on launch and after sign-in, applying tombstones as local deletes. Conflicts resolve last-write-wins by `updated_at`. The outbox survives app restarts.
- **Secrets.** The database password is never stored in the repo; migrations are applied with the Supabase CLI or psql from the shell. The anon key is public and lives in `App/Config/Supabase.plist`.
- **Milestone and push.** When Plans A, B, and H (auth + sync) are complete and the smoke test passes, the branch is merged onto `origin/main` (`git@github.com:UBParker/animalapp.git`, currently holding only a LICENSE) and pushed. Plans C to G follow after the push.

### Addendum v7.1 (2026-09-22): rulings after the three-way review of Plan H

- **Sync mechanism.** Instead of a `SyncOutbox` table, synced models carry `updatedAt` and deletes are recorded as `DeletedRecord` tombstones; `SyncEngine` pushes rows with `updatedAt` after the per-table push watermark plus all outstanding tombstones, and clears tombstones by id only after they were sent. This replaces the outbox sentence above. Required safeguards: last-write-wins is enforced server-side by a `before update` trigger (older `updated_at` never overwrites newer; `deleted_at` is sticky), pulls use a server-stamped `server_updated_at` column as the cursor with ordered, limited pages, remote tombstones obey the same last-write-wins rule, and unresolved parent links never push a null foreign key.
- **Ownership of the local store.** The store owner is recorded the moment a session is established. The store is wiped when a different user signs in, when the owner is unknown and the store is not empty (offline or pre-auth data is never adopted silently), and on a fresh install that finds a session in the keychain. Any in-flight sync is cancelled before a wipe. Sign out uses local scope and does not proceed if the SDK sign-out fails.
- **Release gate.** A release build with no anon key shows a blocking "not configured" screen, never the tabs. The anon key is public and is committed in `App/Config/Supabase.plist`; a guard prevents committing any `sb_secret_` or service-role key.
- **Nonce.** Raw nonce to Supabase, SHA-256 hex to Apple. If Supabase reports a nonce mismatch, the second attempt uses base64url of the digest; dropping the nonce needs Ash's explicit sign-off and is recorded as an accepted replay risk.
- **Storage hygiene.** Deleting a recording also removes its audio object; Settings offers account deletion that removes the user's rows, storage prefix, and auth user through a security-definer function. Built-in tag seeds use deterministic ids so re-seeding after a wipe upserts rather than duplicates.
